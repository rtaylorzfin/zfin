Feature: before/after table-summary across two DB loads (branch zfin-compare-db-loads)

Goal: given two dated DB unload files, load each via `gradle loaddb`, snapshot every
table (row count + content hash), and emit a per-table before/after comparison summary.
Driven automatically by a Jenkins job that mirrors Load-Database's file selection.

Parts:
[x] snapshot script  server_apps/DB_maintenance/postgres/snapshot_table_summary.sh
[x] compare script    server_apps/DB_maintenance/postgres/compare_table_summaries.sh
[x] gradle task       build.gradle: compareLoads -Dbefore=<dump> -Dafter=<dump>
[x] jenkins job       server_apps/jenkins/jobs/Compare-Database-Loads/config.xml
[x] doc               doc/compare-database-loads.md

Known limitation (documented): content hash includes zdb_id / date columns, so ID-churning
loads (drop + reload of equivalent data) flag as `changed`. Future TODO: per-table
meaningful-column hashing (cf. lib/DB_functions/mgte_hash_*.sql).

Future TODO: move compareLoads out of build.gradle into the zfin-utils command.

Design note: snapshot hashes each row then aggregates in hash order (ORDER BY the
row's own md5), NOT by PK/all-columns. This is deterministic, key-agnostic, and
avoids ORDER BY failures on PK-less tables with unorderable column types (json/xml).
